# Oasis Wiki

For game UI reference analysis, reusable control libraries, project-specific asset catalogs and preview caches, UI Tree planning, or screenshot-to-UI work, use the integrated Game UI Design System branch in `references/game-ui-design-system.md` before MCP WidgetBlueprint operations.

For AI UI generation, text-first SOURCE guidance, editable layer extraction, component confirmation, or RedCliff delivery planning, use the separate Cowart UI Production branch in `references/cowart-ui-workflow.md`. For staged Agent questions, approvals, review gates, backtracking, and result reporting around that existing workflow, also read `references/oasis-ui-agent-interaction.md`.

For a real `.psd` source whose group/layer hierarchy must become a UMG WidgetTree, also read `references/cowart-ui/psd-to-umg.md`. Parse the PSD structure instead of inferring hierarchy from a flattened preview. Preserve parentage, stack order, bounds, visibility, opacity, masks, and stable source IDs in a reviewed manifest before any WidgetBlueprint delivery.

For user-facing instructions on starting, continuing, reviewing, confirming components, planning UMG, or authorizing editor delivery, read `references/cowart-ui/usage-guide.md`. Treat `更新 Skill/UI 工具链说明` as documentation-only; ambiguous editor-sync wording requires one clarification and never grants editor-write permission by itself.

Natural-language requests such as `做一下 UI 生成`, `我有一个 UI 需要生图`, `帮我做个 UI`, or `启动 UI 生图工具` immediately enter Cowart UI Production at SOURCE in the same conversation. The native Companion workflow is enabled. When the user explicitly asks to open, start, continue, or review the UI workflow or Workbench, use the native handoff and open the applicable registered page. Verify the session/page identity before presenting it. Opening Companion or Workbench never authorizes editor writes.

When the conversation reveals that the user is generating a UI image, making a UI mockup, slicing or separating controls, extracting components, splitting layers, or importing PSD hierarchy into UI controls, and the current task has not already entered Cowart UI Production, proactively ask once: `检测到你正在进行 UI 生图、控件拆分或 PSD 层级导入，是否需要我接入 UI 工具链，帮你同步当前进度并继续协助？` If accepted, first summarize and synchronize the current context, artifacts, and stage, then continue the applicable workflow stage. Open Companion or Workbench only when the user explicitly requests it or a generated handoff must be presented for the requested review. If declined, continue the current task and do not ask again during that task.

When the user says `确认导入`, `按刚保存的位置导入`, or an equivalent explicit phrase after using UI Workbench, read the applicable registered page's `layout-review.json`. Require `artifact_type: ui_layout_review`, `schema_version: 1`, `status: pending_chat_confirmation`, and a current `source.session_sha256`. Workbench saving does not automatically return data to the conversation. Use a page already identified in the current context, or the sole pending snapshot for the current project when there is exactly one; never choose only by newest time when multiple pages are pending. Report the page, revision, save time, and change summary before continuing. 保存布局不等于编辑器写入授权: exact WidgetBlueprint `load_path`, project match, frozen UMG plan, read-only preflight, project-external backup, and explicit authorization for the specific write remain mandatory.

When built-in `image_gen` is unavailable, an official environment Key is absent, the active credential belongs to a custom provider, or the default image model is unavailable, do not stop before querying the active provider. Run `scripts/game-ui/generate_with_codex_provider.py --discover-image-models`; this metadata-only `/models` discovery reports `generation_attempted: false`, never performs an automatic paid probe, and never prints credentials. List the `confirmed`, `likely`, and `uncertain` candidates with their evidence for the developer. Keep `selection_required: true` even when only one candidate exists, and generate only after the developer selects a model and explicitly authorizes provider-direct generation.

Use this skill for Oasis/绿洲启元 and 和平精英 UGC development questions. The bundled wiki is the source of truth for Lua APIs, editor workflows, gameplay systems, UI, templates, troubleshooting, and examples. The project-pattern references summarize generic UGC Lua architecture habits without private project names, local paths, or planning details.

## Workflow

0. Before analyzing, reviewing, teaching, or changing project code, read `references/predecessor-code-policy.md`. Use `git blame` and `git log` to identify ownership of the exact blocks involved, inspect same-type predecessor implementations before the final response, and apply the protected-author, style, and attribution rules from that reference.
1. Classify the user request with `references/task-router.md`. Choose one primary task branch and at most one secondary branch before loading detailed references.
2. Search first; do not load the full wiki into context. Start with `references/wiki/README.md` to confirm the synchronized catalog version, update time, and available indexes when official docs are relevant. When the user asks whether the official wiki changed, run `scripts/sync_official_wiki.py --dry-run`; only run the write mode after an explicit synchronization request. For new official developer-forum material from 绿洲启妹, run `scripts/sync_official_forum.py --dry-run` first and write the forum collection only after explicit synchronization approval.
3. For feature/API/system questions (`怎么用`, `怎么做`, `有没有`, `支持吗`, class/API names, editor feature names, templates, systems, components), search the current synchronized official wiki teaching docs in `references/wiki/*.md` before giving a conclusion, together with these focused references:
   - `references/wiki/官方API参考手册.md` for class, enum, function, parameter, and API existence.
   - `references/wiki/新增内容_1.37版本.md` for new/changed official features, 1.37 behavior, the UGCAskQ MCP setup guide, MCP Server panel options, `.mcp.json`/SSE configuration, logging, safety notes, and troubleshooting.
   - `references/wiki/论坛经验帖_绿洲启妹.md` for official forum tutorials, practical setup steps, and implementation examples.
   - `references/wiki/官方宣讲会回顾.md` for official 宣讲会/绿洲工坊 briefings and version details the official wiki snapshot does not cover yet, including 功能模板 (组队/玩家档案/排行榜好友榜), 管理平台 grouping and 工单管理, lobby 灰度/新潜榜/Banner changes, 赛事征集, and 光谱计划.
4. Use `references/wiki/README.md` to choose the matching official wiki teaching document by category, such as UI, GamePlay systems, skills, items, monsters, editor workflows, templates, debugging, and performance. Use `references/wiki/API参考索引.md`, `references/wiki/代码示例库.md`, and `references/wiki/术语表.md` as focused lookup indexes.
5. Choose answer style with `references/answer-modes.md`. Use normal mode by default. Read `references/teaching-mode.md` only when the user explicitly requests teaching mode, detailed explanation, step-by-step guidance, or beginner-friendly walkthrough output. In teaching mode, do not directly modify UGC project files; give file-line edit instructions instead. During an active teaching task, the user's `收尾` instruction explicitly exits teaching mode, authorizes direct implementation of the already explained and agreed current-task plan, and leaves the conversation in normal mode after implementation and verification; it does not authorize unrelated scope, protected-history edits, binary editor writes, deletion, commit, push, paid actions, or other separately gated operations.
6. Follow the branch chosen by `references/task-router.md`:
   - Project analysis: `references/project-cache.md`, `references/project-planning-memory.md`, and targeted project files.
   - Feature development: `references/feature-development-flow.md`, plus `references/code-style.md` when editing or reviewing Lua.
   - Debugging/errors: available logs first, then `references/pitfalls.md` and only the branch tied to the symptom.
   - MCP operation: `references/mcp-integration.md`, then either `references/mcp-ui-widget.md` or `references/mcp-datatable.md`; use both only for genuinely mixed UI+table tasks.
   - Config/balancing: table schema/usage lookup, `references/mcp-datatable.md` when editor tables are involved, and project code consumers.
   - UI/interaction: UIManager, `Script/UI`, existing button bindings, and `references/mcp-ui-widget.md` only for WidgetBlueprint work.
   - UI design system: `references/game-ui-design-system.md`, then only the required file under `references/game-ui/`. For existing UMG hierarchy comparison, reusable Item/List design, or replacement-readiness review, read `references/game-ui/umg-hierarchy-patterns.md`. Resolve the project profile and its `.game-ui-system` manifests before extracting controls or generating a page. Use `project_library_asset` references only for confirmed components or resolved semantic items.
   - Cowart UI production: `references/cowart-ui-workflow.md` and `references/oasis-ui-agent-interaction.md`, then `references/cowart-ui/component-extractor.md` or `references/cowart-ui/delivery.md` for the active stage. For a `.psd` source, also read `references/cowart-ui/psd-to-umg.md` before parsing or mapping layers. Use the UI design system as its upstream style and UI Tree gate. The interaction reference adds approval orchestration only; it does not add persistent task state or runtime communication.
   - Project safety: `references/pitfalls.md`, binary asset precautions, dirty file distinction, and backup rules.
7. For MCP/editor automation, search `references/wiki/新增内容_1.37版本.md` for `UGCAskQ MCP 使用说明` when setup or official behavior is uncertain. Confirm the editor MCP Server is running locally, the SSE URL/port match the panel, call logging is enabled when debugging, and backups for `.uasset` files live outside the UGC project tree. PIE debugging must use `ue_pie` for start, stop, Lua hot reload, and client/DS Lua execution, and must not use computer control to click editor PIE controls. Every `ue_pie` call with `action=start` must explicitly set `simulation_platform=mobile`; never omit this field and never use the PC platform value `pchd`. Other actions do not need the platform field. If `ue_pie` is unavailable, verify the MCP connection and `tools/list`; report the blocker and do not fall back to computer control. Follow the full fast-iteration and verification rules in `references/mcp-integration.md`. If Codex direct/native MCP registration enters reconnect loops (`正在重新连接 1/5`, `正在重新连接 4/5`, `reconnecting`) or fails with stream-completion errors (`stream disconnected before completion`, missing `response.completed`), immediately stop retrying native MCP and use the local HTTP proxy workflow in `references/mcp-integration.md` instead. Also use the proxy when the user asks for `长连接 MCP` / `MCP 代理` / `绕过直连 MCP` / `让 Codex 用 MCP`.
8. For log/debugging questions, inspect available project/editor logs first when possible, and distinguish PIE logs, local `Clientlog`/`DSlog`, phone logs, management-platform DS logs, MCP call logs (`Saved/log/MCP_YYYYMMDD.log`), and battle logs. Use `ue_pie` plus its PIE session resource and returned log paths for runtime iteration; filesystem log reads remain valid verification and are not computer control.
9. If the user asks whether knowledge should be added to this skill, read `references/skill-evolution.md`, follow the controlled update protocol, and run `scripts/check-skill-hygiene.ps1` before finishing. After any Skill or Companion update, also read `references/companion-versioning.md` and run `python scripts/check_companion_skill_versions.py`; do not report success unless it returns `status=match` for the actual running Companion process.
10. For flattened AI-generated UI that needs reusable controls, read `references/cowart-ui-workflow.md`, `references/cowart-ui/precision-reconstruction.md`, and `references/cowart-ui/transparent-asset-extraction.md`. Use one complete mother background plus transparent or intentionally translucent controls. Keep runtime-dynamic text, numbers, timers, progress, labels, and hit targets native by default; developer-confirmed fixed visual lettering may be extracted as a glyph-only transparent asset without silently changing runtime bindings. Require checker/alpha inspection, clean parent layers, recomposition, profile/catalog validation, and developer review before Stage 3 confirmation.
11. If a generated UI browser fallback shows `localhost` / `ERR_CONNECTION_REFUSED`, do not call it a Companion crash until the Companion process and log are checked. Treat it as a dead ephemeral Workbench worker first: the generated supervisor should restart the worker, while the native Companion retries briefly and falls back to the persisted session catalog. If the supervisor itself is gone, regenerate or reopen the session through Companion instead of keeping a stale port tab.
12. Hard code-change rule: follow `references/predecessor-code-policy.md`. Code owned by the protected predecessor is frozen by default and must remain byte-for-byte untouched whenever an additive hook elsewhere can solve the task. Other authors' code may be changed only with the smallest compatible diff after ownership and same-type references are checked. Extend existing feature variables, functions, owners, and flows before adding parallel ones; if the existing implementation is genuinely unusable, state the concrete semantic, ownership, lifecycle, compatibility, or verification reason before introducing anything new.
13. Keep defensive code narrow: guard only real boundary risks such as user input, missing config, async UI lifecycle, RPC payloads, destroyed actors, or optional data. If an internal required value is supposed to exist for the whole flow, prefer letting the bug surface over wrapping every step in repeated `if` / `UE.IsValid` checks.
14. For implementation answers, cite relevant local file paths and line numbers when possible. Preserve existing teammate behavior, names, call order, formatting, RPC names, event IDs, save keys, and project style unless the change is required and explained.
15. UI replacement/rebinding invariant: when the request is to connect, replace, migrate, or rebind a new UI, treat the existing runtime behavior as the complete contract. Only map the new Widget controls onto the existing button callbacks, events, RPCs, data owners, and refresh functions. Do not add or change gameplay rules, validation, configuration, save data, replication, rewards, costs, limits, or unrelated code. If a compatibility edit is truly required for the new Widget names or hierarchy, make only the smallest local edit needed to preserve the old behavior.
16. Protected-author hard stop: before any project code or Lua binding edit, run `git blame` and `git log` on the exact target block and resolve protected ownership from private local agent instructions. Never store or reveal the protected person's identity in this repository or in user-facing output. Protected code is untouchable. The only possible exception is an unavoidable UI replacement/rebinding compatibility edit; before touching even one protected line, stop and request explicit, task-specific user authorization using anonymous wording such as `受保护的历史代码`, with the exact file/function/lines, why an external hook cannot work, and the proposed minimal diff. Without that explicit authorization, do not edit the block.
17. Unexpected project artifact gate: whenever a project check, Git inspection, pre-commit review, release check, or editor validation finds files that the UGC editor does not consume or that appear generated accidentally, such as `__pycache__/`, `*.pyc`, temporary scripts, prompts, manifests, contact sheets, or unexpected Markdown files, stop before deleting, committing, reverting, or pushing. Inspect the file and its Git state, explain what the file type is and what this exact file appears to do, then ask whether the user wants it removed and optionally ignored. Markdown is not automatically junk: preserve known project documentation and inspect unexpected `.md` files by path and content. If the file was committed or pushed, report the commit and remote state and ask whether to create a cleanup commit that deletes it. Never amend, reset, revert a push, force-push, or rewrite published history without separate explicit authorization; if the user asks to withdraw the pushed history, explain the risk and confirm the exact branch and commits first. Follow `references/pitfalls.md` for the full classification flow.
18. Feature evidence-first rule: before explaining, planning, or implementing a gameplay or UI feature, resolve the configured primary predecessor from private local instructions and search same-type implementations authored by the primary predecessor only by default. Search the current project first, then the available `RedCliff`, `StarMon`, and `StealItem` repositories. Search the bundled knowledge base in the same pass. Use the secondary predecessor only when the user explicitly requests a broader predecessor search; other authors are relevant only for exact-block ownership, compatibility, and current-project foundation checks. Validate every candidate against the current project's runtime/data ownership. When a relevant code or knowledge-base document is confirmed, the user-facing answer must include the exact standalone sentence `已查到相关实现` before the evidence-backed plan. Report code evidence as project, file, function/table, and commit; report documentation evidence as knowledge-base file and section/article. If neither source has a relevant result, say so without inventing a precedent. Never reveal the configured identities.
19. Knowledge-first feature change gate: Before modifying or adding a gameplay or UI feature, configuration-backed behavior, editor workflow, or other UGC capability, search the bundled knowledge base in `references/wiki/*.md` before the first edit. Search with the feature name, system name, class/API names, and likely synonyms; inspect any related official implementation or usage guidance before choosing the change. A confirmed knowledge-base hit uses the same `已查到相关实现` acknowledgement and documentation evidence format as rule 18. Before a third implementation attempt, when two consecutive edit-and-verify attempts have not succeeded, stop editing and search the bundled knowledge base again using the observed symptom and exact error text, then reconcile the result with the current project and same-type predecessor implementation before trying another change.
20. Official Wiki link rule: When a confirmed relevant implementation or usage guide comes from a synchronized official Wiki article, the user-facing evidence must include a clickable Markdown link to that exact official article, for example `官方 Wiki：[文章标题](https://developer.gp.qq.com/wikieditor/#/catalog/<文档ID>)`. Copy the URL from the matched article's own `官网原文` metadata; do not guess a URL from its title or category. If several official articles materially support the answer, link each cited article. This applies in addition to reporting the local knowledge-base file and section/article. Distilled local references are not official Wiki articles and must not be presented as official links. For an official API hit, use the exact API URL already present in the matched entry when available; otherwise link only the official API root and state that no exact deep link was confirmed.
