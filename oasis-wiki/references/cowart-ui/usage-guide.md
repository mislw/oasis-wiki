# UI 工具链使用说明

这页说明用户怎样启动、继续和验收 Oasis Companion 的 `UI 生图工具链`。它描述的是对话入口和每个阶段的下一步，不会因为一句模糊指令自动修改 UGC 编辑器资产。

## 怎么开始

可以直接对 Codex 说：

- `启动 UI 工具链`：进入当前对话的 SOURCE 工具链，并打开 Oasis Companion 的原生 UI 工作流。
- `帮我做 UI` / `帮我做一个商店界面`：进入新 UI 的 SOURCE 阶段，Codex 会先确认页面用途、风格和必要参考。
- `我有一张 UI 图`：把现有图片作为视觉或布局参考导入，不必重新生图。
- `继续上次的 UI`：先恢复最近的可验证页面或 Workbench 会话，再从未完成的审核阶段继续；找不到唯一会话时只询问一次目标页面。

已有图片时可以直接附图，并说明它是 `风格参考`、`布局参考`，还是 `要继续拆分的成品图`。没有图片时，说明页面用途、主要按钮、必须展示的信息和期望风格即可。

## 自动识别提示

Codex 检测到你正在做 UI 生图、界面效果图、切控件、拆控件、组件提取或图层拆分，但当前任务还没有进入工具链时，会询问：

```text
检测到你正在进行 UI 生图或控件拆分，是否需要我接入 UI 工具链，帮你同步当前进度并继续协助？
```

每个任务最多询问一次。同意后，Codex 会先同步当前进度，整理已有输入、产物、阶段和下一步，再继续协助；拒绝后继续当前任务，不会重复询问。只有用户明确要求打开/继续工作台，或任务需要展示刚生成的审核会话时才会打开 Companion；这不会自动授权编辑器写入。

## 每个阶段能说什么

| 阶段 | 工具链正在做什么 | 用户可以说 |
| --- | --- | --- |
| SOURCE | 收集页面目标、参考图和已有组件 | `参考这张图做兑换界面`、`沿用上次的国风样式` |
| VISUAL | 生成或导入完整 UI 视觉稿 | `生成一版`、`把标题区域再亮一点`、`这版视觉通过` |
| WORKBENCH_REVIEW | 在 Workbench 检查层级、透明边缘、色差和可移动区域 | `打开 Workbench`、`关闭按钮复用组件库`、`这个背景有色差，重做这一层` |
| COMPONENT_CONFIRMATION | 确认哪些图层进入组件库，哪些只属于当前页面 | `确认这个关闭按钮为通用组件`、`只保留大的，旧的小图标删除` |
| UMG_REQUIREMENTS | 把已确认视觉整理为 UMG 层级、原生控件和资源计划 | `先给我看 UMG 计划`、`文字和数值保持原生控件` |
| EDITOR_DELIVERY | 按冻结计划备份并写入指定 WidgetBlueprint | `按这个计划写入 WBP_xxx，我确认执行` |
| FINAL_REVIEW | 检查编辑器视觉、交互、Lua/数据绑定和回滚点 | `对比最终效果`、`检查按钮点击和数值刷新` |

视觉通过、组件确认、UMG 计划通过和编辑器交付是不同门禁。前一个阶段通过，不自动代表后一个阶段也被授权。

## 保存布局与原对话确认

Workbench 的 `保存布局` 会在页面会话目录写入 `layout-review.json`，状态为 `pending_chat_confirmation`。它只保存当前控件的完整布局和结构，不会自动回传到对话，也不会创建新的 Codex 任务。

回到原对话后，可以说 `确认导入` 或 `按刚保存的位置导入`。Codex 会读取当前对话已识别页面的快照；如果当前项目恰好一份待确认快照，可以使用该快照；如果有多份，必须先确认页面，不能只按保存时间选择。Codex 还会对照 `session_sha256`，源 `session.json` 已变化时必须要求重新保存。

保存布局不等于编辑器写入授权。继续写入前仍需精确 WidgetBlueprint `load_path`、项目匹配、已冻结 UMG 计划、只读预检、项目外备份，以及用户对本次具体写入的明确授权。

## 组件复用

- 已有通用按钮、关闭图标、货币图标或面板皮肤时，先解析组件库中的语义键、资源身份和有效预览，再决定复用。
- 只有状态为 `active` 且预览可读的组件可以直接复用；候选项、旧版本、重复小图或带错误背景的预览不能冒充成品。
- 复用图标时只保留一个视觉来源。已有 Unreal `native_preview` 时不得再叠加透明底图、额外背景或 fallback `×`。
- 新版本确认后，同一界面的旧版本和被替代的小规格副本按清理规则移除，但不得误删源图、重建结果或仍被其他页面引用的资产。

## 说明更新与编辑器授权

- `更新 Skill`、`更新 UI 工具链说明`、`把规则加到 Skill` 都表示**只更新说明**；这不等于授权修改编辑器。
- `同步编辑器里面的`、`放进编辑器`、`给编辑器也更一下` 等说法如果没有指出目标资产和执行范围，必须先澄清一次，不能自行推断为写入许可。
- 编辑器写入前必须同时具备：精确的 WidgetBlueprint 路径、已冻结的 UMG 计划、项目外备份，以及用户对本次写入的明确授权。
- 未满足这些条件时，只能生成说明、视觉稿、Workbench 结果、组件决策或交付计划，不得写入 `.uasset`、WidgetBlueprint、Lua、DataTable 或其他 UGC 项目文件。

## 常用一句话

```text
启动 UI 工具链，继续上次的兑换界面。
用这张图做布局参考，风格沿用现有组件库。
打开 Workbench，我先检查图层和组件复用。
视觉通过，进入组件确认，暂时不要写编辑器。
先生成 UMG 计划，给我确认后再执行。
按已确认计划写入指定 WidgetBlueprint，我授权本次修改。
```
