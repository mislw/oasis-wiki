# 网络相关优化

> 本文介绍如何在场景中对怪物进行网络性能优化，降低客户端和网络开销，提升玩家体验。

---

## 功能概述

当场景中存在大量怪物时，每个怪物都需要进行网络同步（位置、状态、动画等），这会产生大量的网络流量和客户端计算开销。通过合理配置网络参数，可以在不影响玩家体验的前提下，大幅降低性能消耗。

**核心思路**：离玩家越远的怪物，同步精度可以越低——因为玩家很难注意到远距离怪物的微小位移差异。

---

## 一、网络复制基础参数

在实体编辑器中选中怪物 Actor 后，在属性面板的 **Replication** 分类下可以看到以下关键配置项：

![image.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/lzuNhimage.png)

### 1.1 网络更新频率（NetUpdateFrequency）

**作用**：控制怪物每秒最多向客户端同步多少次状态。

| 配置项   | 说明      |
| -------- | --------- |
| 默认值   | 20 Hz     |
| 推荐范围 | 5 ~ 20 Hz |
| 单位     | 次/秒     |

**配置建议**：

| 怪物类型               | 推荐值     | 说明                             |
| ---------------------- | ---------- | -------------------------------- |
| 近战 Boss / 高速移动怪 | 15 ~ 20 Hz | 近距离战斗需要高频同步，保证手感 |
| 普通巡逻怪物           | 5 ~ 10 Hz  | 移动较慢，适度降低即可           |
| 远程站桩怪 / 低速NPC   | 2 ~ 5 Hz   | 状态变化少，低频就够用           |
| 装饰性背景NPC          | 1 ~ 2 Hz   | 几乎不需要高精度同步             |

> **特别提示**：降低网络更新频率是最直接有效的优化方式。怪物数量多的场景（50+），建议将普通怪物的频率设置为 `5~10 Hz`，可以显著降低网络和 CPU 开销。

### 1.2 最小网络更新频率（MinNetUpdateFrequency）

**作用**：当怪物长时间没有状态变化时（例如站定不动），系统会自动降低同步频率，最低降到此值。

| 配置项   | 说明       |
| -------- | ---------- |
| 默认值   | 1.0 Hz     |
| 推荐范围 | 0.5 ~ 2 Hz |

**注意事项**：

- 此值必须**小于**网络更新频率，否则会出现异常行为
- 当怪物开始移动后，频率会自动恢复到正常值

### 1.3 网络剔除距离平方（NetCullDistanceSquared）

**作用**：超出此距离的怪物将**完全不进行网络同步**——即客户端完全看不到该怪物。

| 配置项 | 说明                    |
| ------ | ----------------------- |
| 默认值 | 22,500,000（约 150 米） |
| 单位   | 厘米的平方（cm²）      |

**⚠️ 重要提醒：此值是距离的平方！**

需要按以下方式计算：

| 期望剔除距离 | 应填入的值  | 计算方式       |
| ------------ | ----------- | -------------- |
| 50 米        | 25,000,000  | 5000 × 5000   |
| 80 米        | 64,000,000  | 8000 × 8000   |
| 100 米       | 100,000,000 | 10000 × 10000 |
| 150 米       | 225,000,000 | 15000 × 15000 |
| 200 米       | 400,000,000 | 20000 × 20000 |

**配置建议**：

| 场景       | 推荐距离     | 对应值                    |
| ---------- | ------------ | ------------------------- |
| 开放大世界 | 150 ~ 200 米 | 225,000,000 ~ 400,000,000 |
| 中型关卡   | 80 ~ 100 米  | 64,000,000 ~ 100,000,000  |
| 室内场景   | 30 ~ 50 米   | 9,000,000 ~ 25,000,000    |

> **使用场景**：如果您的关卡比较小（比如室内副本），可以将剔除距离设置得更小。超出这个距离的怪物完全不占用网络资源，优化效果非常明显。

## 二、距离分档网络优化（核心推荐）

这是编辑器提供的**一体化怪物网络优化方案**，根据怪物与玩家的实际距离，自动切换不同的同步精度。距离越远，同步越"粗略"，性能消耗越低。

![image.png](https://cgugc-video-test-1258633575.cos.ap-shanghai.myqcloud.com/wiki_picture/iKZXmimage.png)

### 2.1 功能开关

在怪物属性面板中找到 **Network Optimization** 分类：

| 配置项               | 说明                 | 推荐设置                         |
| -------------------- | -------------------- | -------------------------------- |
| 启用距离分档网络优化 | 是否启用此功能       | 场景 NPC 数量 ≥ 50 时建议`开启` |
| 距离检测间隔         | 多久检测一次距离变化 | `0.5` 秒（默认值，无需修改）     |

> **注意**：此功能仅在客户端生效，不影响服务器逻辑。

### 2.2 分档配置说明

开启后，需要配置一个**距离分档数组**，每个档位定义在某个距离范围内的同步参数。系统会根据怪物与玩家的实时距离，自动切换到对应档位。

**匹配规则**：

1. 计算怪物到本地玩家的距离
2. 从数组第一档开始查找，找到第一个`距离 ≤ 距离阈值`的档位
3. 如果距离超过所有档位阈值，使用最后一档（兜底）

每个档位包含以下参数：

| 参数                 | 作用                   | 单位       |
| -------------------- | ---------------------- | ---------- |
| 距离阈值             | 该档位生效的最大距离   | 厘米（cm） |
| 网络更新频率         | 该距离下的同步频率     | Hz         |
| 移动组件Tick间隔     | 控制移动计算的精度     | 秒         |
| 网络平滑更新最大距离 | 位置跳变多大时取消平滑 | 厘米       |
| 网络不平滑更新距离   | 位置跳变多大时直接瞬移 | 厘米       |
| 移动平滑模式         | 位置插值的算法         | 枚举       |
| 胶囊体碰撞模式       | 客户端碰撞检测类型     | 枚举       |

### 2.3 参数详解

#### 网络更新频率（Hz）

控制该距离下怪物的同步频率。

| 距离范围          | 推荐值     | 效果                     |
| ----------------- | ---------- | ------------------------ |
| 近距离（≤30m）   | 15 ~ 30 Hz | 位置同步精确，战斗手感好 |
| 中距离（30m~80m） | 5 ~ 10 Hz  | 适度降低，玩家不易察觉   |
| 远距离（>80m）    | 1 ~ 3 Hz   | 仅保持基本同步           |

#### 移动组件Tick间隔（秒）

控制怪物移动计算的更新频率。值越大，计算越少，性能越好。

| 距离范围 | 推荐值         | 说明                         |
| -------- | -------------- | ---------------------------- |
| 近距离   | `0` 或 `0.033` | 每帧或30帧计算一次，保证流畅 |
| 中距离   | `0.1` ~ `0.2`  | 降低更新频率                 |
| 远距离   | `0.3` ~ `0.5`  | 远距离移动精度不重要         |

#### 移动平滑模式

控制怪物位置的插值方式：

| 模式                  | 效果                     | 推荐使用场景     |
| --------------------- | ------------------------ | ---------------- |
| `指数`（Exponential） | 接近目标时减速，最自然   | 近距离，表现优先 |
| `线性`（Linear）      | 匀速插值，中规中矩       | 中距离           |
| `已禁用`（Disabled）    | 不插值，直接跳到目标位置 | 远距离，性能优先 |

#### 胶囊体碰撞模式

控制怪物在客户端的碰撞行为（仅影响客户端，不影响服务器判定）：

| 模式                            | 效果                             | 推荐使用场景                 |
| ------------------------------- | -------------------------------- | ---------------------------- |
| `已启用碰撞（查询和物理）`（QueryAndPhysics） | 完整碰撞，可被射线检测且阻挡玩家 | 近距离，需要完整交互         |
| `纯查询（无物理碰撞）`（QueryOnly）           | 可被射线检测到，但不阻挡玩家     | 中距离，需要被瞄准但无需阻挡 |
| `纯物理（不查询碰撞）`（PhysicsOnly）           | 仅保留物理碰撞，但不会被射线检测或 Trace 命中     | 中近距离，需要阻挡但无需被瞄准锁定，或用于优化射线检测性能 |
| `无碰撞`（NoCollision）         | 完全禁用碰撞                     | 远距离，不需要任何交互       |

## 三、推荐配置方案

### 方案一：标准三档配置（推荐）

适用于大多数 PVE 场景，100 个以内怪物：

| 档位 | 距离阈值      | 更新频率 | Tick间隔 | 平滑最大距离 | 不平滑距离 | 平滑模式 | 碰撞模式   |
| ---- | ------------- | -------- | -------- | ------------ | ---------- | -------- | ---------- |
| 近   | 3000（30m）   | 20 Hz    | 0.033s   | 400          | 1000       | 指数     | 查询和物理 |
| 中   | 8000（80m）   | 8 Hz     | 0.15s    | 1000         | 3000       | 线性     | 仅查询     |
| 远   | 20000（200m） | 2 Hz     | 0.5s     | 5000         | 10000      | 关闭     | 无碰撞     |

**适用场景**：割草玩法、怪物攻城、PVE关卡等常见场景

### 方案二：大规模场景配置

适用于怪物数量非常多（200+）的极端场景：

| 档位 | 距离阈值      | 更新频率 | Tick间隔 | 平滑最大距离 | 不平滑距离 | 平滑模式 | 碰撞模式   |
| ---- | ------------- | -------- | -------- | ------------ | ---------- | -------- | ---------- |
| 近   | 1500（15m）   | 15 Hz    | 0.05s    | 500          | 1500       | 指数     | 查询和物理 |
| 中近 | 4000（40m）   | 6 Hz     | 0.2s     | 1500         | 4000       | 线性     | 仅查询     |
| 远   | 10000（100m） | 2 Hz     | 0.5s     | 5000         | 10000      | 关闭     | 无碰撞     |

**适用场景**：大量小怪刷新、怪物潮、塔防等

### 方案三：极简两档配置

适用于小型场景，对性能要求不高：

| 档位 | 距离阈值      | 更新频率 | Tick间隔 | 平滑最大距离 | 不平滑距离 | 平滑模式 | 碰撞模式   |
| ---- | ------------- | -------- | -------- | ------------ | ---------- | -------- | ---------- |
| 近   | 5000（50m）   | 15 Hz    | 0.033s   | 500          | 1000       | 指数     | 查询和物理 |
| 远   | 15000（150m） | 3 Hz     | 0.3s     | 3000         | 8000       | 关闭     | 无碰撞     |

**适用场景**：少量精英怪、Boss战、小副本

## 四、配置步骤

### 4.1 配置基础网络参数

1. 在实体编辑器中选中怪物 Actor
2. 在属性面板中找到 **Replication** 分类
3. 设置`网络更新频率`为合适的值（普通怪物建议 `10`）
4. 设置`最小网络更新频率`为 `1.0`
5. 根据场景大小设置`网络剔除距离平方`

### 4.2 开启距离分档优化

1. 在属性面板中找到 **Network Optimization** 分类
2. 勾选`启用距离分档网络优化`
3. 在`距离分档配置`数组中点击"+"添加档位
4. **按距离从小到大的顺序**依次添加配置（重要！）
5. 根据场景需要参考上方推荐方案填入参数

### 4.3 验证效果

配置完成后，运行游戏进行测试：

- 走近怪物时，观察移动是否流畅
- 走远后，观察是否有明显卡顿或瞬移（远距离轻微瞬移是正常的）
- 检查客户端帧率是否有改善

## 五、注意事项

### 常见问题

**Q：配置后怪物远距离会突然瞬移？**
A：这是正常现象。远距离档位的同步频率较低，位移会有一定的跳变。如果瞬移过于明显，可以适当提高远距离档位的网络更新频率或调大平滑距离。

**Q：距离分档配置后不生效？**
A：请检查以下几点：

- 是否已勾选`启用距离分档网络优化`开关
- 档位数组是否按距离阈值**从小到大排列**
- 至少需要配置一个档位

**Q：碰撞模式改成无碰撞后，远距离怪物打不到了？**
A：碰撞模式只影响客户端。服务器上的碰撞判断不受影响，伤害计算仍然正常。如果需要远距离用枪瞄准怪物（如射线检测），建议中距离档使用`仅查询`模式而非`无碰撞`。

**Q：距离剔除和距离分档有什么区别？**
A：

- **网络剔除距离**：超出此距离的怪物**完全消失**，客户端看不到
- **距离分档优化**：在剔除距离以内，根据远近调整同步精度，怪物仍然可见

### 配置注意

1. **档位排序**：距离分档数组必须按距离阈值从小到大排列，否则匹配逻辑会出错
2. **最后一档兜底**：确保最后一档的距离阈值设置得足够大，覆盖所有可能的距离
3. **最小频率 < 更新频率**：`最小网络更新频率`必须小于`网络更新频率`
4. **平方值陷阱**：设置`网络剔除距离平方`时，记住要用"距离 × 距离"计算

## 六、性能收益参考

以 100 个怪物的 PVE 场景为例，使用标准三档配置后：

| 指标             | 优化前 | 优化后       | 提升     |
| ---------------- | ------ | ------------ | -------- |
| 客户端 Tick 开销 | 基线   | 降低 40%~60% | 显著     |
| 网络带宽占用     | 高     | 明显降低     | 较大     |
| 玩家体验         | 卡顿   | 流畅         | 明显改善 |

> **实际收益取决于场景中怪物数量和分布情况。怪物数量越多、分布越分散，优化效果越明显。**
